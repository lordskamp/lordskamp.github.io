# Таблиця та заміри

Сайт: https://lordskamp.github.io/Zavod/

Адмін-панель: https://t.me/obpresyvanya_bot?startapp=admin

## Як записати замір

1. Відкрити застосунок через Telegram-акаунт **@Lordskamp** → **Адмін**.
2. Обрати провід і переріз. Форма підставить відомі практичні значення. Довідка й прогноз не записуються як замір.
3. Вписати перевірені числа та, за потреби, примітку.
4. Натиснути **Зберегти замір**. Запис з’явиться у **Попередніх замірах**.

Щоб змінити числа в калькуляторі, перед збереженням позначити **Застосувати ці значення в калькуляторі**. Без цієї позначки замір залишається лише в журналі. Нові значення спільні для всіх кольорів одного режиму. У ПВ3 суцільний колір робиться одним екструдером, жовто-зелений — двома: їхні заміри зберігаються окремо. Для інших проводів калькулятор використовує останній застосований замір цього проводу й перерізу. Старі записи з кольорами збережено в історії.

Порожнє поле означає «не записано», а не нуль. Зміна кількості екструдерів ПВ3 підставляє практичні значення обраного режиму. Для інших проводів зміна режиму очищає оберти шнека й робочу швидкість: їх треба ввести для нового режиму. Незавершена форма зберігається на цьому пристрої. Після помилки зв’язку можна повторити збереження — той самий замір не дублюється.

**Таблиця → Фото** показує довідку, практичні записи й пояснення. Власнику також доступна **Історія змін**. Старі заміри можна взяти за основу нового. Заміри доступні для кожної марки з друкованої довідки, навіть якщо рукописного запису ще немає.

План барабанів зберігається на пристрої. Заміри та робоча таблиця — на сервері, спільно для телефона й комп’ютера. Для редагування з комп’ютера також треба відкрити Mini App у Telegram.

## Дані та доступ

- Перелік: 70 марок і варіантів із друкованої довідки, 122 довідкові позиції. Початкові 37 рукописних рядків із `Zavod/data.js` та власні заміри збережені. Невідомі параметри лишаються порожніми; спірні рукописні варіанти записані в примітках.
- API: `https://zavod-data.lordskamp.workers.dev`; налаштування: `wrangler.zavod.jsonc`.
- D1 `zavod-data`: `recipes` — робочі рядки, `measurements` — журнал, `recipe_history` — попередні версії, `settings` — власник.
- Читання робочої таблиці відкрите. Журнал, історія та всі зміни доступні лише власнику.
- Сервер перевіряє HMAC-підпис Telegram `initData`, термін 12 годин та акаунт. Перший вхід із підписаним іменем `Lordskamp` прив’язує доступ до незмінного числового Telegram ID. Далі збіг імені іншого акаунта не дає доступу.
- Секрет бота зберігається лише як Cloudflare Worker secret `TELEGRAM_BOT_TOKEN`. Клієнт не містить його й не використовує `initDataUnsafe` для авторизації. Підписані дані не записуються в localStorage або журнали сервера.
- Збереження рядка перевіряє версію. Якщо з іншого пристрою вже збережено новіші дані, старі їх не перезапишуть: замір залишиться в журналі. Треба оновити таблицю та взяти замір за основу ще раз.
- Повторне застосування початкових SQL-записів не перезаписує власні заміри.

## Оновлення

```powershell
pnpm run test:zavod
pnpm run lint
pnpm exec wrangler deploy --dry-run -c wrangler.zavod.jsonc
pnpm exec wrangler d1 migrations apply zavod-data --remote -c wrangler.zavod.jsonc
pnpm exec wrangler deploy -c wrangler.zavod.jsonc
```

Сайт публікується через GitHub Pages. Інші Worker цього репозиторію використовують окремі конфігурації. Секрети вводити через захищений запит `wrangler secret put`, не додавати їх у Git.

Перевірки: розрахунки довжини, авторизація Telegram, прив’язка власника, відхилення чужих записів, окремі кольори, повторне збереження, конфлікт версій, історія та пагінація журналу. Перевірка браузерної форми виконується лише з окремою локальною тестовою базою й тестовим секретом. Вона не створює виробничих замірів.
